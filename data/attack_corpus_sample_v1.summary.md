# MCP-DETECT attack corpus v1 — SAMPLE (public)

**This is the fast sample of the full attack corpus.** It contains 119 of 378
malicious records (17 of 54 sessions) from
`data/full/attack_corpus_full_v1.jsonl`, selected to fire every shipped
detection rule at least once across all five techniques. **Recall numbers reproduced
from this file are sample-level, not the full-corpus numbers in
`docs/PHASE4-REPORT.md`** — see the table below for exactly which counts are
which. The complete corpus and the exact `docs/PHASE4-REPORT.md` inputs are
available under `data/full/`.

**Files**:
- `attack_corpus_sample_v1.jsonl` (119 lines, JSONL, schema v1)
- `rugpull_alerts_sample_v1.jsonl` (5 lines) — **not** a slice of the full
  corpus's derived-drift stream. `baseline/watch.py` is stateful (TOFU:
  trust-on-first-use), so its output depends on what a given
  `(tool_name, server_command)` pair's *first* observation in a run looks
  like. This file was generated by a **fresh, isolated watcher run against
  only this sample's telemetry** (empty state, same discipline
  `framework/coverage.py`'s own evasion-corpus fixtures already use) — not
  extracted from the full corpus's own `rugpull_alerts_full_v1.jsonl`,
  which reflects a different (larger) state history and would not match.
- `.sha256` files for both, same convention as `data/benign_corpus_v2.jsonl.sha256`.
- `attack_corpus_sample_v1.golden_matches.json` — precomputed, real
  `wazuh-logtest` final-matched-rule-id per line, captured live at freeze
  time. `framework/repro_offline.py --tier sample` (the default, no
  Docker/Ollama/Wazuh needed) replays against this to reproduce the
  sample-level numbers below.

**Frozen**: 2026-07-11, from `data/full/attack_corpus_full_v1.jsonl`.
**Extended 2026-07-12** with SAF-T1104 (sensitive absolute-path read, rule
`100109`) — 21 sample records / 3 sessions added, and all golden files
recaptured live against the new ruleset. Rule-sync verified at re-capture time
(sha256 `0c03e47ed44bb42fde54f402b79be3f8f5ad902c0f8c6258ddd27068d903f0f8`;
was `1104f282…` before `100109` was added).

Rug pull is the one technique where the sample is the *entire* technique —
only 4 task_ids exist in total, so there was no reason to shrink it further;
the sample honestly reproduces the full "3/3 drift shapes" claim, not a
subset of it. Tool poisoning, credential exfil, and path traversal are
genuine subsets — their sample-level recall (below) is real but smaller
than the full-corpus numbers.

**Path traversal's sample recall is honestly 2/3, not 3/3 — reproduced
faithfully, not smoothed over.** The sample deliberately keeps
`attack_path_traversal_v01_env_overlap`: its path (`../../.env`) correctly
fires `100101` (the credential-exfil read-hop rule) instead of `100108`,
exactly the documented, deliberate overlap-resolution behavior in
`detections/SAF-T1105_path_traversal/detection.yaml` ("the other 2
correctly defer to `100101` by design... technique-level 8/8" —
`docs/PHASE6-T1105-REPORT.md`'s own "reported precisely rather than rounded
up" discipline, applied here too). Technique-level (any rule firing counts
as detected) this sample is 3/3; `100108`'s own-rule recall is 2/3,
proportional to the full corpus's own 6/8. **`docs/PHASE4-REPORT.md` never
published a path-traversal number at all** — `SAF-T1105` was added in
Phase 6, after PHASE4-REPORT.md was frozen; its own recall is published
separately in `docs/PHASE6-T1105-REPORT.md`, and `framework/parity_check.py`
itself never checks it against PHASE4 either, for the same reason.
